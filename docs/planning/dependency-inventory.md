Five installed packages have no discovered top-level notice: `@docsearch/css`, `@docsearch/js`, `@docsearch/sidepanel-js`, `@iconify-json/simple-icons`, and `@rolldown/binding-linux-x64-gnu`. Local notice bytes were not independently checked against npm tarball integrity, and nested notices/header obligations are not fully classified.

Sixteen packages have no discovered named notice in the receipt, including the wrapper; exact identities are in `unresolved`. Absence of such a filename is not a finding that the package has no license.
- SQLite 3.50.2's amalgamation/header hashes are bound to `libsqlite3-sys` provenance. Its source copyright disclaimer is recorded separately from the Rust wrapper's expression. The owned C VFS adapter has no selected project license.
- WASI SDK 27.0 executable/library hashes and archive digest are retained, but the installed SDK and retained archive contain no named license/notice files. Corresponding WASI libc/compiler-runtime/SDK source revisions and notices remain unresolved. Recorded library inventory is broader than linkage: the wallet build explicitly links static `libc`.
- Rust toolchain copyright documents and license texts are retained as local supplemental evidence, alongside the compiler and target-library hashes. Per-linked-object attribution, other standalone codec capsule producer graphs, and canonical proving-parameter distribution terms still need coverage before whole-package closeout.

Metadata includes choices and licenses with distinct obligations (for example npm `MPL-2.0` and `CC-BY-4.0`, and Cargo alternatives). Nothing here selects an alternative or asserts that distributing notices alone satisfies it. Project license selection remains outside authorization.

The extraction used only existing files and Node standard libraries; its retained script path/hash is in the inventory. No dependency install, producer modification, build or network audit was run.
